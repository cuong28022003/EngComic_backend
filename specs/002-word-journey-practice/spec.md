# Feature Specification: Word Journey — 7-Stage Practice System

> **Perspective**: Business / Product Owner & Developer  
> **Purpose**: Answer the question **"WHAT & WHY"**  
> **Extends**: Feature 001 (Unified Vocabulary Learning System)  
> **Feature ID**: 002  

---

## 1. Overview & Objective

- **Feature ID**: 002
- **Feature Name**: Word Journey — 7-Stage Mastery Practice
- **Priority**: P1
- **Depends On**: Feature 001 (CardEntity, ExampleSentence, WordRelation, SRS fields must exist)

### 1.1 Objective

Upgrade the practice pipeline from a linear 5-exercise session into a **progressive 7-stage word mastery journey**. Each word travels through stages 0→6 independently. A word cannot advance until it passes the current stage's criteria. All exercise content is generated purely from **static data already stored in MongoDB** (no real-time AI calls during practice).

### 1.2 Key Design Decisions

| Decision | Choice | Rationale |
| :--- | :--- | :--- |
| Stage model | 7 stages (0–6) on `CardEntity.stage` | Existing field, just extend range from 5 to 6 |
| Progress fields | All on `CardEntity` (no separate `word_progress` collection) | Avoids two-collection syncing overhead; atomic updates |
| New fields needed | `confidenceScore`, `lastExerciseType`, `seenExampleIds` (already exists) | Minimal schema change |
| Stage 6 availability | Only when `status = 'mature'` | Gate prevents premature "real-world" exercises |
| Audio recording | Stored as base64 / blob reference; NOT processed server-side | Client-side only; server stores URL reference only |
| Daily Life Challenge | Server-side random selection of 3–5 mature words | Runs as a separate API endpoint, not inside SRS queue |
| SRS + confidence_score | When confidence < 3, ratchet interval down by 30% even if answer was correct | Prevents mechanical memorization without real fluency |

## 2. Stage Definitions

```
Stage 0  → Imported, not started (status = 'new')
Stage 1  → Recognition (identify meaning)
Stage 2  → Context & Nuance (formal/informal, collocations)
Stage 3  → Pronunciation (audio self-assessment)
Stage 4  → Assisted Production (fill-in, word ordering)
Stage 5  → Free Production (write & self-check)
Stage 6  → Real-world Application (only when status = 'mature')
           ↓
     SRS loop + Random Maintenance Review
```

### Stage 1 — Recognition
- **Goal**: Understand basic meaning
- **Exercises**:
  - Flashcard flip (word + IPA + audio ↔ meaning + example)
  - Multiple choice: pick correct meaning from 4 options (3 distractors from same user's cards)
  - Audio → pick correct word from 4 options
- **Pass condition**: 3 consecutive correct answers
- **Distractor source**: `CardRepository.findRandomCardsByUserIdExcluding(userId, cardId, limit=3)`

### Stage 2 — Context & Nuance
- **Goal**: Distinguish formal/informal, learn collocations
- **Exercises**:
  - Formal vs informal choice: show 2 examples (one formal, one informal), user picks the correct formality for a given scenario
  - Collocation fill-in: "make a ___ decision" — gaps generated by removing target word from collocations in `relations` where `type='collocation'`
  - Synonym comparison: show target word + synonym from `relations` (type='synonym'), ask user to explain difference (self-assess)
- **Pass condition**: score ≥ 3/4

### Stage 3 — Pronunciation
- **Goal**: Stress, linking sounds, sentence intonation
- **Exercises**:
  - Listen to audio (Free Dictionary API URL stored in `audio` field) → record self → compare (Web Speech API, client-side)
  - Read full example sentence aloud (not just target word)
- **Pass condition**: User self-rates ≥ 3 stars
- **Skip condition**: If `partOfSpeech = null` AND no audio URL → auto-pass with note "pronunciation not available"

### Stage 4 — Assisted Production
- **Goal**: Produce language with scaffolding
- **Exercises**:
  - Fill-in-the-blank: remove target `word` from example sentence text
  - Word ordering: shuffle words of an example sentence (server shuffles, client re-orders)
  - Short answer: given a prompt, answer using the target word (self-check)
- **Pass condition**: score ≥ 2/3

### Stage 5 — Free Production
- **Goal**: Fully autonomous sentence creation
- **Exercises**:
  - Write 1 original sentence using the word
  - Self-check checklist (client-side): contains the word? basic grammar correct? natural?
  - Compare with stored example sentences
  - Record self reading own sentence → store audio URL reference
- **Pass condition**: User self-rates ≥ 4/5 on all 3 self-check items

### Stage 6 — Real-World Application *(only when status = 'mature')*
- **Goal**: Spontaneous use; confidence assessment
- **Exercises**:
  - **Situational Recall**: describe a scenario, user writes how they'd use the word (no position hint)
  - **Role-play MCQ**: 1 conversation context, pick best response from 4 options
  - **Conversation Chain**: 2–3 mature words used together in 1 situation (multi-word challenge)
  - **Confidence Rating**: 1–5 stars ("Would you use this naturally in real life?") → stored in `confidenceScore`
- **Pass condition**: `confidenceScore ≥ 3`; updates SRS `nextReview` based on confidence

## 3. SRS Enhancements

### 3.1 Standard SM-2 Rules (unchanged from Feature 001)
- Correct → increase interval using `easeFactor`
- Wrong → reset interval to 1 day, increment `lapses`
- Max interval: **365 days**

### 3.2 New: Confidence Score Influence
```
IF stage == 6 AND confidenceScore < 3:
    interval = max(1, interval * 0.7)  // ratchet down 30%
    status = 'learning'  // pull back from mature if needed
```

### 3.3 Leech Detection (enhanced)
```
IF wrongCount >= 4:
    status = 'leech'
    stage = 1  // reset to Recognition
    nextReview = today + 1 day
```
- Leech cards are excluded from normal SRS queue
- Shown in a special "Leech Review" session (user must add a memory tip before clearing leech status)

### 3.4 Daily Review Cap
- Max 30 cards per day in the regular SRS queue
- Priority: overdue longest → overdue shortest → due today
- If queue > 30: block new cards from being added to that day's session; show "Review backlog" warning

### 3.5 Random Maintenance Review
- Weekly job: pick 5 random `status='mature'` cards (regardless of `nextReview`)
- Inject them into that week's practice sessions with `lastExerciseType` alternated

## 4. New Fields Required on `CardEntity`

| Field | Type | Default | Notes |
| :--- | :--- | :--- | :--- |
| `confidenceScore` | `int` | `0` | 1–5; only updated in Stage 6 |
| `lastExerciseType` | `String` | `null` | Last exercise variant run; used to alternate |
| `seenExampleIds` | `List<String>` | `[]` | Already exists in Feature 001 |

> `stage` already exists (int, 0–5 currently). Range simply extends to 0–6.

## 5. New API Endpoints

### Practice Session

| Method | Path | Description |
| :--- | :--- | :--- |
| `GET` | `/api/card/practice/queue` | Returns ordered list of due cards (respects daily cap, leech exclusion) |
| `GET` | `/api/card/{id}/exercise` | Returns exercise data for current stage of this card |
| `POST` | `/api/card/{id}/submit` | Submits answer/quality for current stage; advances stage or updates SRS |
| `GET` | `/api/card/leech` | Returns all leech cards for user |
| `POST` | `/api/card/{id}/clear-leech` | Clears leech status after user adds memory tip |

### Daily Life Challenge

| Method | Path | Description |
| :--- | :--- | :--- |
| `GET` | `/api/card/daily-challenge` | Returns today's challenge: 3–5 random mature cards with situational prompts |
| `POST` | `/api/card/{id}/confidence` | Updates `confidenceScore` and adjusts SRS interval |

### Distractors (internal helper)

| Method | Path | Description |
| :--- | :--- | :--- |
| `GET` | `/api/card/distractors?cardId={id}&limit=3` | Returns 3 random cards (different from target) for MCQ distractor use |

## 6. Exercise Data Shape (per stage)

The `GET /api/card/{id}/exercise` endpoint returns a stage-specific payload:

```json
// Stage 1 — Recognition
{
  "stage": 1,
  "exerciseType": "multiple_choice_meaning",
  "target": { "id": "...", "word": "decision", "ipa": "...", "audio": "..." },
  "question": "Chọn nghĩa đúng của từ 'decision'",
  "options": [
    { "id": "...", "text": "sự quyết định", "isCorrect": true },
    { "id": "...", "text": "sự do dự", "isCorrect": false },
    { "id": "...", "text": "sự từ chối", "isCorrect": false },
    { "id": "...", "text": "sự thỏa thuận", "isCorrect": false }
  ]
}

// Stage 2 — Context
{
  "stage": 2,
  "exerciseType": "collocation_fill",
  "question": "Điền vào chỗ trống: 'make a ___ decision'",
  "answer": "decision",
  "hint": "Đây là collocation từ dữ liệu đã lưu"
}

// Stage 4 — Assisted Production
{
  "stage": 4,
  "exerciseType": "fill_blank",
  "sentence": "The manager made a quick ___ about the budget.",
  "answer": "decision",
  "exampleId": "ex_001"
}

// Stage 6 — Real-world
{
  "stage": 6,
  "exerciseType": "situational_recall",
  "situation": "Bạn đang họp với sếp và cần diễn đạt rằng bạn vừa đưa ra một quyết định quan trọng.",
  "targetWord": "decision",
  "relatedWords": ["crucial", "implement"]
}
```

## 7. Permissions & Constraints
- All endpoints require JWT authentication
- Users can only access their own cards
- Stage 6 exercises are only generated if `status = 'mature'`; otherwise return `403 Forbidden` with message `"Stage 6 requires mature status"`
- Daily challenge returns HTTP `204 No Content` if user has no mature cards yet
